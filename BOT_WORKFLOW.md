# Инструкция для бота-кодера (синхронизация с GitHub)

С 1 мая 2026 кодовая база `/var/www/saas-crm/` на VPS — **полноценный git-репозиторий**, связанный с https://github.com/nedvedskaya/detailpro через SSH deploy key.

**Раньше:** бот правил файлы напрямую → правки терялись при следующем `deploy.sh` с Mac (rsync затирал).

**Теперь:** GitHub — единственный источник правды. Mac и сервер оба пушат туда. Всё видно в истории коммитов.

---

## После любой партии правок выполни на сервере:

```bash
cd /var/www/saas-crm

# 1. Проверь что изменилось
git status

# 2. Подтяни возможные правки от Оли (с её Mac), чтобы не было конфликтов
git fetch origin main
git rebase origin/main   # или git pull --rebase origin main

# 3. Закоммить свои правки
git add -A
git commit -m "<тип>: <описание>

<развёрнутое описание что и зачем поменял, если нужно>"

# 4. Запушь в main на GitHub
git push origin main

# 5. Применить изменения (билд + рестарт saas-crm.service)
bash scripts/deploy.sh
```

### Формат коммитов

`<тип>(<scope>): <короткое описание>` — соблюдай существующий стиль:
- `feat(bookings): multi-service в брони`
- `fix(payments): минимум 50 ₽ к оплате`
- `ui(profile): кнопка меньше`
- `refactor(dry): извлечь helper в lib/`
- `docs: PROJECT_OVERVIEW обновлён`

Тип: `feat` / `fix` / `ui` / `refactor` / `docs` / `chore` / `test` / `build` / `ops`.

### Что НЕ коммитить (в `.gitignore`):

- `.env` — секреты прода (никогда не уезжает в git)
- `node_modules/` — ставится через `npm ci`
- `client/dist/` — собирается на сервере при деплое
- `*.bak` — временные бэкапы (если делаешь — потом удали)
- `*.log`, `*.dump`

## Если конфликт при rebase

Например, Оля только что что-то закоммитила с Mac, ты пытаешься запушить и получаешь конфликт:

```bash
# 1. Покажи себе конфликтные файлы
git status

# 2. Открой каждый, разреши <<<<<<< HEAD ... ======= ... >>>>>>>
# 3. После разрешения:
git add <разрешённые файлы>
git rebase --continue
git push origin main
```

Если конфликт сложный — **остановись** и напиши Оле в Telegram, что есть конфликт в файле X. Лучше пусть она разрулит, чем сломать прод.

---

## Чего НЕ делать

- ❌ **Не запускай `git push --force`** — это перезапишет историю и потеряет правки Оли.
- ❌ **Не правь файлы вне git** (например, через `vim` без последующего commit/push) — следующий деплой откатит изменения.
- ❌ **Не делай `bash scripts/deploy.sh` без push** — деплой тянет с GitHub, незапушенные правки не доедут.
- ❌ **Не коммить `.env`** — это секреты прода.

## Если что-то пошло не так

```bash
# Откат к последней рабочей версии
cd /var/www/saas-crm
git log --oneline -10           # найти последний рабочий коммит
git reset --hard <commit-hash>
git push --force-with-lease origin main   # ТОЛЬКО если уверен и согласовал с Олей
bash scripts/deploy.sh
```

Лучше — напиши Оле в Telegram, что что-то сломалось, и опиши что делал.
